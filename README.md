# ascii-cube

ASCII-анимация трёх вращающихся кубов в терминале.

Два бинарника:

| Цель | Файл | Описание |
|------|------|----------|
| `cube` | `cube.c` | монохромные грани `@ $ ~ # ; +` |
| `cube_colored` | `cube_colored.c` | те же грани в RGB (ANSI 24-bit) |

## Сборка и запуск

```bash
make          # cube и cube_colored (-O2)
make cube     # только монохромный
./cube
./cube_colored
```

Выход: `Ctrl+C` (курсор и режим терминала восстанавливаются).

Другие цели:

```bash
make test     # smoke-тест обоих бинарников
make clean
```

Ручная сборка без Make:

```bash
clang -O2 -o cube cube.c -lm
clang -O2 -o cube_colored cube_colored.c -lm
```

Минимальный размер (см. `-Oz` / `strip`):

```bash
make CFLAGS='-Oz -flto -fno-unroll-loops -fno-vectorize -fno-slp-vectorize' LDFLAGS='-lm -flto -Wl,-dead_strip'
strip cube cube_colored
```

## Тесты

`make test` собирает оба бинарника и на ~0.5 с запускает каждый через `timeout`. Проверяется, что в stdout есть ANSI-escape, фон `.` и стабильно видимые грани `@ $ ~ +` (`#` и `;` часто закрыты z-буфером).

```bash
make test
```

## Что делает программа

Каждый кадр:

1. очищает кадровый буфер и z-буфер;
2. считает матрицу поворота по углам `A`, `B`, `C`;
3. проецирует грани трёх кубов (половины ребра 20, 10 и 5) в ASCII;
4. печатает кадр в терминал (alternate screen);
5. увеличивает углы и ждёт остаток периода кадра (~16 мс, `nanosleep`).

Размер окна берётся через `TIOCGWINSZ` (с потолком `MAX_WIDTH` × `MAX_HEIGHT`) и обновляется по `SIGWINCH`.

Грани кодируются символами `@ $ ~ # ; +`.

## Оптимизации

Исходный вариант считал `sin`/`cos` внутри каждой проекции, шагал по грани с шагом `0.6` при аргументах типа `int` (из‑за этого одни и те же точки рисовались по несколько раз) и выводил кадр через `putchar` по одному символу.

### 1. Матрица поворота один раз за кадр

Углы за кадр не меняются. Вместо повторных вызовов `sin`/`cos` на каждую точку кадр начинается с `updateRotation()`: `sinf`/`cosf` и девять коэффициентов `R00…R22`. Дальше точка — это умножение координат на матрицу.

### 2. Целая решётка вместо шага `0.6`

`calculateX/Y/Z` принимали `int`, поэтому `float`-шаг `0.6` обрезался к нулю ещё до формулы. Для куба со стороной 20 получалось ~2,8× лишних проекций при той же картинке. Теперь грань обходится целыми координатами `[-half, half)`.

### 3. Инкремент по грани

После поворота угла грань — это аффинная плоскость. `renderFace` задаёт угол и два единичных шага в пространстве параметров и накапливает `x, y, z` сложениями, без умножения матрицы на каждой точке.

### 4. Корректные границы экрана

Раньше индекс считался как `xp + yp * width` и проверялся одним диапазоном. Координаты вроде `xp = 200`, `yp = -1` попадали внутрь буфера и портили чужие пиксели. Теперь отсекаются `xp` и `yp` по отдельности.

### 5. Один вывод кадра

Вместо цикла `putchar` строки копируются в `frameOut` с `\n` после каждой и пишутся одним `fwrite`. Нулевой столбец больше не подменяется символом перевода строки. Для stdout включена полная буферизация.

### 6. Общая отрисовка куба

Три почти одинаковых цикла заменены на `renderCube(half, horizontalOffset)`.

### 7. Размер терминала

Ширина и высота синхронизируются с окном (`ioctl` / `SIGWINCH`); `memset` чистит только используемые `width * height` пикселей. Курсор скрывается на время работы и возвращается по `SIGINT` / `SIGTERM` / `atexit`.

### Что не вошло

**Backface culling** пробовали, но не оставили. В анимации `A` и `B` растут одинаково, поэтому `R22 = cos(A)·cos(B) ≥ 0`, и грань `#` почти всегда сзади. В оригинале редкие пиксели `#` всё же пробивались по краям через z-буфер; жёсткое отсечение убирало символ `#` из картинки.

## Замеры

Только расчёт кадра (без паузы кадра), clang, arm64, среднее по 400 кадрам:

| Сборка   | Было   | Стало   | Ускорение |
|----------|--------|---------|-----------|
| `-O0`    | 4,63 мс | 0,25 мс | ~19×     |
| `-O2`    | 0,98 мс | 0,093 мс | ~11×    |
| `-O3`    | 0,19 мс | 0,095 мс | ~2×     |

Полный кадр с выводом при `-O2`: ~1,11 мс → ~0,089 мс. Период `FRAME_NS` (~16 мс) по-прежнему задаёт нижнюю границу длительности кадра на экране.

Число проекций на кадр: **35 604 → 12 600** (те же уникальные целые точки без повторов).
